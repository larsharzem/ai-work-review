---
description: 把小改动转写成精简开发文档 awaiting-review（微改 <task description>）
---

小改动的轻量入口：按精简模板新建开发文档（Basics / Requirements / Acceptance criteria / Delivery 四节），状态=awaiting-review，请作者去面板点「调整」或「通过」，不要开工。

**只省写作篇幅，不省流程**：「Basics」的 状态 / 模块 / Target directory / Delivery date 必须填齐且 Delivery date 留空——缺字段时面板「通过」「closed」是空操作、`整合` 捞不到这份文档，且不会报错。

**不适用**：delivered 代码要改 → `变更`；交付结果与验收不符（BUG）→ `整改`；波及共享组件或要论证边界 → `需求`。

先加载并遵守技能 dev-review 的 SKILL.md：优先项目级 `.cursor/skills/dev-review/SKILL.md`（ZCode 为 `.zcode/skills/`），没有则读用户级 `~/.cursor/skills/dev-review/SKILL.md`（ZCode 为 `~/.zcode/skills/`）。

执行 dev-review 的子命令「微改」，参数：$ARGUMENTS

按技能执行，不要往仓库写模板文件。开发文档固定写在 `docs/dev-docs/<module>/`。
